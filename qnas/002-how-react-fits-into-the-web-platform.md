# 002. Q&A: How React fits into the web platform

Review how React works with the browser and the other parts of a web application. The questions focus on responsibilities and on tracing a typical UI update.

## Browser, React, and tooling

### 1. Where does React fit in a web application?

React is the UI library. It helps describe a component tree and keep its rendered result aligned with current inputs and state. The browser, React DOM, project tooling, network, and server each have separate responsibilities.

### 2. Does React replace the browser or the DOM?

No. The browser provides the DOM, JavaScript runtime, CSS processing, event handling, and visual rendering. React DOM is the renderer that lets React manage DOM content in a browser container.

### 3. What is the difference between React and React DOM?

React provides the component and UI model. React DOM connects that model to browser DOM nodes and provides APIs such as `createRoot` and `hydrateRoot`.

### 4. Does a browser execute JSX directly?

No. JSX is source syntax. A compatible build tool or runtime transforms it into JavaScript the browser can execute. The exact tooling depends on the project.

### 5. What does a build tool usually do in a React project?

It may transform JSX, resolve JavaScript modules, process CSS and other assets, run a development server, and produce optimized files for deployment. Those responsibilities are not the component model itself.

### 6. Is the development server the same as the backend?

Not necessarily. A development server serves files and may proxy API requests during local development. The backend is application server logic that handles requests, permissions, business rules, and data operations. Some frameworks combine these concerns, but their roles remain distinguishable.

## Roots and the browser DOM

### 7. What is the root container?

It is the browser DOM element where a client-rendered React tree is mounted, often an element such as `<div id="root"></div>`.

### 8. What is a React root?

A root is the connection React DOM creates to manage React-rendered content inside a container. The root is different from both the DOM element and the component rendered at the top of the tree.

### 9. What is the root component?

It is the top component passed to the root for rendering, commonly named `App`. It describes the top of that React component tree.

### 10. Should every component call `createRoot`?

No. Roots are generally created at application entry points. Components are nested inside the root, and a framework may create the root automatically.

### 11. Does React own every element on a page?

No. React manages the DOM inside its root container. Surrounding page content can remain owned by existing HTML or another system. Avoid having two systems independently mutate the same React-managed region.

### 12. Can a page have more than one React root?

Yes. A page that gradually adopts React can have separate roots for independent regions. A typical app built entirely with React usually has one root. Do not mount multiple roots into the same DOM region.

### 13. What happens to existing child HTML when `createRoot` renders?

A client-only `createRoot` takes over the container's contents, so existing child HTML in that container is cleared on the first render. Keep unrelated server or static content outside the root. If the container holds React-generated server HTML, use hydration instead.

### 14. What is the difference between `createRoot` and `hydrateRoot`?

`createRoot` starts a client-rendered tree in a DOM container. `hydrateRoot` attaches React to matching HTML that was already generated by React on a server or at build time. They serve different starting conditions.

## Rendering and interactions

### 15. What is the simplified path from source code to a displayed page?

A tool prepares the source; the browser loads HTML, JavaScript, and CSS; JavaScript creates or hydrates a React root; React renders components; React DOM updates the container; then the browser lays out and paints the result. Real applications can involve more steps and different scheduling.

### 16. What happens after a user clicks a React button?

The browser dispatches an event. React's event handling calls the supplied handler. The handler may request a state update. React renders the UI for the new inputs, React DOM applies necessary DOM updates, and the browser displays them.

### 17. Does React directly handle pixels and layout?

No. React describes UI and React DOM updates browser DOM. The browser handles CSS rules, layout, painting, and displaying pixels.

### 18. Does React automatically make HTTP requests?

No. Application code or a framework/library decides when to request data and how to handle the result. React renders the UI based on the data and state it receives.

### 19. What is the difference between frontend and backend responsibilities?

Frontend code runs in the browser and presents the interface. Backend code runs on a server and can protect secrets, enforce authorization, validate input, apply business rules, and access databases. A framework may let developers organize both sides in one project.

### 20. Is it safe to put a private API key in a React component?

No. Code and values delivered to the browser can be inspected by users. Keep private credentials and privileged operations on the server, and verify authorization there.

## Rendering strategies and integration

### 21. What is client rendering?

The browser runs the app's JavaScript and creates the React UI in a container, typically with `createRoot`. The initial container may be empty until the app renders.

### 22. What is server rendering?

A server or build process renders React output into HTML before the client app runs. The browser can receive meaningful markup earlier. A framework often coordinates server rendering and related data loading.

### 23. What is hydration?

Hydration is when React attaches client behavior to matching React-generated HTML that already exists in the DOM. The initial client output should match the server output so React can reuse that markup.

### 24. Is server rendering the same as React Server Components?

No. Server rendering is a way to generate HTML before the client runs. React Server Components are an architecture for deciding which components run on the server versus the client. They may be used together, but they are different concepts and RSC needs compatible framework or bundler support.

### 25. Can React manage just one section of an existing site?

Yes. Add a dedicated DOM container for the interactive section and mount React there. Keep the rest of the page in its existing system if that is useful.

### 26. What is React Native's relationship to React DOM?

They use the React component model with different renderers. React DOM targets browser DOM; React Native renders native platform UI. Web-specific DOM elements and APIs do not become native views automatically.

### 27. Does React include a universal router?

No. React core does not prescribe one router. A project can choose a routing library or use a router included by its framework.

### 28. Can I directly modify a node inside a React root?

Avoid it. React expects to manage the root's UI, so manual mutations may conflict with later renders. For a specific imperative task such as setting focus, use a ref and keep the integration bounded.

## Quick scenarios

### Scenario A: A team wants React only for a search widget

Is a full-site rewrite required?

**Answer:** No. The page can keep its existing structure and mount a React root in a dedicated search region.

### Scenario B: Server-generated React HTML is visible before JavaScript loads

Should the app call `createRoot` and render over it?

**Answer:** No. It should use `hydrateRoot` so React attaches to the existing matching HTML.

### Scenario C: A user clicks a filter and the list changes

Which part changes first: the DOM directly or application state?

**Answer:** The handler requests an application state update. React renders from the new state, and React DOM applies the needed DOM changes.

### Scenario D: The app needs a database password

Should the password be included in browser JavaScript?

**Answer:** No. The browser is user-visible. Keep the credential and database operation on the server.

## Quick self-check

1. Which part provides browser DOM APIs: React or the browser?
2. Which package entry point provides browser root APIs?
3. What should be used to attach to React-generated server HTML?
4. Does a React UI automatically know how to fetch data?
5. In a React root, who should normally control the container's child DOM?
6. Can the rest of a page remain outside React?

### Suggested answers

1. The browser.
2. `react-dom/client`.
3. `hydrateRoot`.
4. No. The app, framework, or data library must arrange data loading.
5. React DOM, based on the React tree.
6. Yes. React can manage a dedicated region of a larger page.
