# Loading, Empty, Success, and Error States — Example

This Vite demo loads a local product list and renders an explicit request state:

- a loading message while the request is pending;
- a list when the request succeeds with results;
- an empty state when the request succeeds without matches;
- an error with a working Retry button when the request fails.

The local response is delayed slightly so the loading state is easy to see. A checkbox simulates a request failure so you can inspect and recover from the error state without depending on an external service.

## `src/products.js`

~~~js
function wait(milliseconds, signal) {
  return new Promise((resolve, reject) => {
    if (signal?.aborted) {
      reject(signal.reason || new DOMException("Request aborted", "AbortError"));
      return;
    }

    const timeoutId = setTimeout(() => {
      signal?.removeEventListener("abort", handleAbort);
      resolve();
    }, milliseconds);

    function handleAbort() {
      clearTimeout(timeoutId);
      signal.removeEventListener("abort", handleAbort);
      reject(signal.reason || new DOMException("Request aborted", "AbortError"));
    }

    signal?.addEventListener("abort", handleAbort, { once: true });
  });
}

export async function loadProducts(
  query,
  { signal, simulateFailure = false } = {},
) {
  // The short delay makes the loading state visible in this local demo.
  await wait(650, signal);

  if (simulateFailure) {
    throw new Error("Demo failure: turn off the failure option and retry.");
  }

  const response = await fetch("/products.json", { signal });

  if (!response.ok) {
    throw new Error("Could not load products: HTTP " + response.status);
  }

  const products = await response.json();
  const normalizedQuery = query.trim().toLowerCase();

  if (!normalizedQuery) {
    return products;
  }

  return products.filter((product) => {
    const searchableText =
      product.name + " " + product.category + " " + product.description;

    return searchableText.toLowerCase().includes(normalizedQuery);
  });
}
~~~

The wait observes the optional signal so cleanup can stop the demo delay too. In a real application, pass the signal to the actual asynchronous operation and follow the API's cancellation behavior.

## `src/App.jsx`

~~~jsx
import { useEffect, useState } from "react";
import { loadProducts } from "./products.js";

function ProductList({ products }) {
  return (
    <ul className="products">
      {products.map((product) => (
        <li className="product" key={product.id}>
          <div>
            <h3>{product.name}</h3>
            <p>{product.description}</p>
          </div>
          <span className="category">{product.category}</span>
        </li>
      ))}
    </ul>
  );
}

function Results({ state, query, onRetry }) {
  if (state.status === "loading") {
    return (
      <p className="loading" role="status">
        Loading products…
      </p>
    );
  }

  if (state.status === "error") {
    return (
      <div className="error" role="alert">
        <p>Products could not be loaded: {state.error.message}</p>
        <button type="button" onClick={onRetry}>
          Try again
        </button>
      </div>
    );
  }

  if (state.data.length === 0) {
    return (
      <div className="empty">
        <h2>No matching products</h2>
        <p>
          No products match “{query}”. Try another search or clear the search
          field.
        </p>
      </div>
    );
  }

  return (
    <>
      <p className="count" role="status">
        {state.data.length}{" "}
        {state.data.length === 1 ? "product" : "products"} found.
      </p>
      <ProductList products={state.data} />
    </>
  );
}

export default function App() {
  const [query, setQuery] = useState("");
  const [requestVersion, setRequestVersion] = useState(0);
  const [simulateFailure, setSimulateFailure] = useState(false);
  const [result, setResult] = useState({
    status: "loading",
    query: "",
    data: [],
    error: null,
  });

  useEffect(() => {
    const controller = new AbortController();
    let ignore = false;

    setResult({ status: "loading", query, data: [], error: null });

    loadProducts(query, {
      signal: controller.signal,
      simulateFailure,
    })
      .then((data) => {
        if (!ignore) {
          setResult({ status: "success", query, data, error: null });
        }
      })
      .catch((error) => {
        if (ignore || controller.signal.aborted) {
          return;
        }

        setResult({ status: "error", query, data: [], error });
      });

    return () => {
      ignore = true;
      controller.abort();
    };
  }, [query, requestVersion, simulateFailure]);

  // Do not show the previous query's state under the newly edited input.
  const visibleResult =
    result.query === query
      ? result
      : { status: "loading", query, data: [], error: null };

  function retry() {
    setSimulateFailure(false);
    setRequestVersion((version) => version + 1);
  }

  return (
    <main className="app">
      <p className="eyebrow">React request states</p>
      <h1>Products</h1>
      <p className="intro">
        Search the local list, inspect the empty state, or simulate a failure
        and retry the request.
      </p>

      <div className="controls">
        <label className="search">
          <span>Search products</span>
          <input
            type="search"
            value={query}
            onChange={(event) => setQuery(event.target.value)}
            placeholder="Try “stationery” or “lamp”"
          />
        </label>

        <button
          className="secondary"
          type="button"
          onClick={() => setRequestVersion((version) => version + 1)}
        >
          Refresh
        </button>
      </div>

      <label className="failure-option">
        <input
          type="checkbox"
          checked={simulateFailure}
          onChange={(event) => setSimulateFailure(event.target.checked)}
        />
        <span>Simulate a request failure</span>
      </label>

      <section
        className="results"
        aria-labelledby="results-heading"
        aria-busy={visibleResult.status === "loading"}
      >
        <h2 id="results-heading">Results</h2>
        <Results state={visibleResult} query={query} onRetry={retry} />
      </section>

      <aside className="notes">
        <h2>Try these states</h2>
        <ol>
          <li>Wait for the initial product list to load.</li>
          <li>Search for “lamp” to see a successful result.</li>
          <li>Search for “does-not-exist” to see a successful empty result.</li>
          <li>
            Turn on the failure option to trigger an error, then press “Try
            again” to turn it off and load the data successfully.
          </li>
          <li>Change the search while loading; old results must not appear for the new query.</li>
        </ol>
      </aside>
    </main>
  );
}
~~~

The state has one `status` field. An empty array is still a successful response; `Results` gives it a separate empty-state message. The query is stored with the result, and `visibleResult` prevents data for an earlier query from being shown as current.

The Effect aborts the previous request and also ignores results from a cleaned-up setup. See [lesson 074](../lessons/074-request-cancellation-and-race-conditions.md) for why those protections have different jobs.

The Retry button starts a new attempt by incrementing `requestVersion`. It also disables the demo failure option so the next request can succeed.

## Common mistakes

- Treating an empty result as a failed request.
- Representing one request with loosely related booleans.
- Forgetting to check `response.ok` before parsing a real API response.
- Displaying old-query data as if it matched the current input.
- Showing an error without an action to recover.
- Rendering an empty generic region while the request is pending.
- Expecting Retry to work if it only hides the error instead of starting a new attempt.
- Using an assertive alert for ordinary loading or success updates.
- Assuming this demo's controlled failure simulates every real network or server failure.

## Key takeaway

Render the state that actually occurred: pending, successful with results, successful but empty, or failed. Associate data with its query, keep loading and error feedback accessible, and make retry start a real request.
