# React DOM Resource Hints and Browser APIs - Example

This Vite example uses local assets to demonstrate the six React DOM resource-hint APIs. DNS and connection hints are optional and only run if you configure an origin you control for separate report assets.

The buttons start work on demand so you can inspect the browser Network panel. A hint does not guarantee that the browser completes or prioritizes a request.

## Create a project

~~~sh
npm create vite@latest resource-hints-demo -- --template react
cd resource-hints-demo
npm install
~~~

Keep the Vite configuration generated by the project and add or replace these files:

~~~text
resource-hints-demo/
├── index.html
├── .env.example
├── public/assets/
│   ├── feature-startup.js
│   ├── legacy-helper.js
│   ├── print-preview.css
│   ├── report-cover.svg
│   ├── report-panel.js
│   └── report-theme.css
└── src/
    ├── App.jsx

~~~

## Optional origin configuration

The example works with local assets without this setting. To try DNS lookup and connection setup for a separate host you control, copy this file to `.env.local`, enter that host's origin, and restart the Vite server:

~~~dotenv
# Set only when report resources are hosted on a separate origin you control.
VITE_REPORT_ASSET_ORIGIN=
~~~

Leave it empty when using only local assets. Do not configure an origin that you do not intend to contact.

## `src/main.jsx`

~~~jsx

import App from "./App.jsx";
import "./styles.css";

const container = document.getElementById("root");

if (!container) {
  throw new Error("The #root container was not found.");
}

createRoot(container).render(<App />);
~~~

## `src/App.jsx`

~~~jsx
import { useState } from "react";
import {
  preconnect,
  prefetchDNS,
  preload,
  preloadModule,
  preinit,
  preinitModule,
} from "react-dom";

const reportOrigin = import.meta.env.VITE_REPORT_ASSET_ORIGIN;

export default function App() {
  const [message, setMessage] = useState("Choose a resource hint.");
  const [showCover, setShowCover] = useState(false);
  const [moduleMessage, setModuleMessage] = useState("");

  function prepareReport() {
    if (reportOrigin) {
      prefetchDNS(reportOrigin);
      preconnect(reportOrigin);
    }

    preload("/assets/report-cover.svg", { as: "image" });
    preload("/assets/report-theme.css", { as: "style" });
    preloadModule("/assets/report-panel.js", { as: "script" });

    setShowCover(true);
    setMessage(
      reportOrigin
        ? "Origin hints and report preloads were requested."
        : "Local image, stylesheet, and module preloads were requested. Configure the optional origin to try DNS and connection hints.",
    );
  }

  function applyPrintStyles() {
    preinit("/assets/print-preview.css", {
      as: "style",
      precedence: "low",
    });
    setMessage("The print stylesheet was inserted and applied.");
  }

  function runClassicScript() {
    preinit("/assets/legacy-helper.js", { as: "script" });
    setMessage("The classic script was requested for evaluation.");
  }

  function evaluateFeatureModule() {
    preinitModule("/assets/feature-startup.js", { as: "script" });
    setMessage("The feature module was requested for evaluation.");
  }

  function checkFeatureModule() {
    setMessage(
      window.featureStartupReady
        ? "The feature module has evaluated."
        : "The feature module is still loading. Check again shortly.",
    );
  }

  async function openReportModule() {
    try {
      const reportModule = await import("/assets/report-panel.js");
      setModuleMessage(reportModule.reportPanelMessage);
    } catch {
      setModuleMessage("The report module could not be imported.");
    }
  }

  return (
    <main className="demo">
      <p className="eyebrow">React DOM resource hints</p>
      <h1>Prepare resources deliberately</h1>
      <p>
        Each action asks the browser to do a different amount of work. Try them
        one at a time and inspect the Network panel.
      </p>

      <div className="actions">
        <button type="button" onClick={prepareReport}>
          Prepare report resources
        </button>
        <button type="button" onClick={applyPrintStyles}>
          Preinit print stylesheet
        </button>
        <button type="button" onClick={runClassicScript}>
          Preinit classic script
        </button>
        <button type="button" onClick={evaluateFeatureModule}>
          Preinit ESM module
        </button>
        <button type="button" onClick={checkFeatureModule}>
          Check module status
        </button>
        <button type="button" onClick={openReportModule}>
          Import preloaded module
        </button>
      </div>

      <p className="status" role="status">{message}</p>

      {showCover && (
        <section className="report" aria-labelledby="report-title">
          <h2 id="report-title">Report preview</h2>
          <img
            src="/assets/report-cover.svg"
            alt="Illustrated report cover"
            width="480"
            height="260"
          />
          <p>The image was preloaded before this preview appeared.</p>
        </section>
      )}

      {moduleMessage && <p className="status">{moduleMessage}</p>}
    </main>
  );
}
~~~

**Prepare report resources** optionally calls `prefetchDNS` and `preconnect`, then preloads an image, stylesheet, and ES module. The image appears after the preload is requested. The stylesheet is downloaded but not applied; the module is fetched but not evaluated until imported.

The other buttons demonstrate activation: `preinit` inserts and applies a stylesheet or evaluates a classic script, while `preinitModule` evaluates an ES module. These calls are separate because their effects differ.

### `public/assets/report-theme.css`

This file is downloaded by `preload`, but that call does not activate the stylesheet.

~~~css
.report {
  border-color: #4264c5;
}

.report h2 {
  color: #24439d;
}
~~~

### `public/assets/print-preview.css`

This file is fetched, inserted, and applied by the stylesheet preinit button:

~~~css
body {
  background: #e8edf7;
}

.demo {
  border-color: #4264c5;
}
~~~

### `public/assets/legacy-helper.js`

This classic script sets a flag when it executes:

~~~js
window.legacyHelperReady = true;
console.info("The legacy helper script was evaluated.");
~~~

### `public/assets/report-panel.js`

This module is requested by `preloadModule` and later imported by the **Import preloaded module** button:

~~~js
export const reportPanelMessage = "The preloaded report module was imported.";
~~~

### `public/assets/feature-startup.js`

This module sets a flag when `preinitModule` evaluates it:

~~~js
window.featureStartupReady = true;
~~~

The global flag is only for demonstration. Production modules should normally expose a defined API rather than communicate through globals.

## Run and observe

Start Vite:

~~~sh
npm run dev
~~~

Try each action separately and inspect the browser Network panel:

1. **Prepare report resources** requests the image, stylesheet, and module before the report preview is rendered. DNS and connection hints run only when the optional origin is set.
2. **Preinit print stylesheet** inserts and applies the print preview stylesheet.
3. **Preinit classic script** requests and evaluates the classic helper.
4. **Preinit ESM module** requests and evaluates the feature module. Check its status after it finishes.
5. **Import preloaded module** imports the module previously requested by `preloadModule`.

The request may be deduplicated with its later use, delayed, or ignored by the browser. This example demonstrates the APIs; it does not promise a speed improvement.

## Common mistakes

- Importing resource hint functions from `react-dom/client` instead of `react-dom`.
- Requesting every hint on initial render whether or not the resource will be used.
- Assuming `preload` applies a stylesheet or evaluates a script.
- Forgetting `precedence` when preinitializing a stylesheet.
- Using `preinit` or `preinitModule` for code that should not run immediately.
- Expecting a hint function to return a promise or guarantee completion.
- Setting the optional origin to a host the app does not actually use.
- Assuming that issuing a hint automatically improves performance.

## Key takeaway

Choose the least eager hint that fits a likely need: DNS lookup, connection setup, download, or activation. Let React and the framework handle routine loading, and use targeted hints for a measured gap.
