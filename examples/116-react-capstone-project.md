# Example: Build and Ship a Complete Accessible React Application

This example builds a small task tracker with React and Vite. It supports adding, completing, deleting, searching, and filtering tasks. It saves changes in the current browser when local storage is available and stays usable in memory when storage is unavailable.

The app is intentionally local and single-user. Do not use browser storage for passwords, tokens, or sensitive data. A multi-user product needs a backend with authentication, authorization, validation, and data-retention rules.

## 1. Create the project

If you do not already have a React project, create one with Vite:

```sh
npm create vite@latest react-task-tracker -- --template react
cd react-task-tracker
npm install
npm run dev
```

Keep the lockfile generated by the package manager in version control. Replace the starter source files with the files below.

## 2. Store and validate tasks

Create `src/task-storage.js`:

```js
const STORAGE_KEY = "react-capstone.tasks.v1";

const starterTasks = [
  {
    id: "starter-components",
    title: "Review the component tree",
    completed: true,
  },
  {
    id: "starter-state",
    title: "Keep state minimal",
    completed: false,
  },
  {
    id: "starter-accessibility",
    title: "Check keyboard focus",
    completed: false,
  },
];

function copyStarterTasks() {
  return starterTasks.map((task) => ({ ...task }));
}

function isValidTask(task) {
  return (
    task !== null &&
    typeof task === "object" &&
    typeof task.id === "string" &&
    task.id.length > 0 &&
    typeof task.title === "string" &&
    task.title.trim().length > 0 &&
    task.title.length <= 120 &&
    typeof task.completed === "boolean"
  );
}

export function loadTaskStore() {
  if (typeof window === "undefined") {
    return {
      tasks: copyStarterTasks(),
      warning: "Browser storage is not available in this environment.",
    };
  }

  try {
    const savedValue = window.localStorage.getItem(STORAGE_KEY);

    if (savedValue === null) {
      return { tasks: copyStarterTasks(), warning: "" };
    }

    const parsedValue = JSON.parse(savedValue);

    if (
      !Array.isArray(parsedValue) ||
      !parsedValue.every(isValidTask) ||
      new Set(parsedValue.map((task) => task.id)).size !== parsedValue.length
    ) {
      return {
        tasks: copyStarterTasks(),
        warning: "Saved tasks could not be read, so a fresh list is shown.",
      };
    }

    // Copy only the supported fields from browser storage.
    const tasks = parsedValue.map(({ id, title, completed }) => ({
      id,
      title,
      completed,
    }));

    return { tasks, warning: "" };
  } catch {
    return {
      tasks: copyStarterTasks(),
      warning: "Browser storage could not be read, so changes may not persist.",
    };
  }
}

export function saveTasks(tasks) {
  window.localStorage.setItem(STORAGE_KEY, JSON.stringify(tasks));
}
```

The loader validates the data before trusting it. If saved data is invalid, it shows the starter list and warning. The app does not immediately overwrite that saved value; it tries to save after the visitor changes the list.

## 3. Build the task form

Create `src/TaskForm.jsx`:

```jsx
import { useId, useState } from "react";

export function TaskForm({ onAddTask }) {
  const [title, setTitle] = useState("");
  const [error, setError] = useState("");
  const inputId = useId();
  const errorId = useId();

  function handleSubmit(event) {
    event.preventDefault();

    const trimmedTitle = title.trim();

    if (!trimmedTitle) {
      setError("Enter a task title.");
      return;
    }

    if (trimmedTitle.length > 120) {
      setError("Use 120 characters or fewer.");
      return;
    }

    onAddTask(trimmedTitle);
    setTitle("");
    setError("");
  }

  return (
    <form className="task-form" onSubmit={handleSubmit} noValidate>
      <label htmlFor={inputId}>New task</label>
      <p className="field-hint" id={inputId + "-hint"}>
        Keep the title to 120 characters or fewer.
      </p>

      <div className="form-row">
        <input
          id={inputId}
          name="title"
          type="text"
          autoComplete="off"
          maxLength={120}
          value={title}
          onChange={(event) => {
            setTitle(event.target.value);
            if (error) setError("");
          }}
          aria-required="true"
          aria-invalid={error ? "true" : undefined}
          aria-describedby={error ? inputId + "-hint " + errorId : inputId + "-hint"}
        />

        <button type="submit">Add task</button>
      </div>

      {error && (
        <p className="form-error" id={errorId} role="alert">
          {error}
        </p>
      )}
    </form>
  );
}
```

The form handles the whitespace-only case itself, so it uses `noValidate` and exposes its own accessible error message. The visible hint stays connected to the field. The browser's `maxLength` also limits typing; the submit-time check keeps the rule explicit in application logic.

## 4. Render one task

Create `src/TaskItem.jsx`:

```jsx
import { useId } from "react";

export function TaskItem({ task, onToggle, onDelete }) {
  const checkboxId = useId();

  return (
    <li className={task.completed ? "task-item is-complete" : "task-item"}>
      <div className="task-main">
        <input
          id={checkboxId}
          type="checkbox"
          checked={task.completed}
          onChange={() => onToggle(task.id)}
        />
        <label htmlFor={checkboxId}>{task.title}</label>
      </div>

      <button
        className="button-secondary"
        type="button"
        onClick={() => onDelete(task.id)}
        aria-label={"Delete task: " + task.title}
      >
        Delete
      </button>
    </li>
  );
}
```

The checkbox has a label, and the delete button identifies the task it affects. A checked checkbox communicates completion independently of the text color or strikethrough.

## 5. Build the application

Create `src/App.jsx`:

```jsx
import { useEffect, useId, useState } from "react";
import { TaskForm } from "./TaskForm.jsx";
import { TaskItem } from "./TaskItem.jsx";
import { loadTaskStore, saveTasks } from "./task-storage.js";
import "./App.css";

function createTaskId() {
  const generatedId = globalThis.crypto?.randomUUID?.();

  if (generatedId) {
    return generatedId;
  }

  return "task-" + Date.now().toString(36) + "-" +
    Math.random().toString(36).slice(2);
}

function TaskFilters({ value, onChange }) {
  const groupName = useId();

  return (
    <fieldset className="filter-group">
      <legend>Show tasks</legend>

      <label>
        <input
          type="radio"
          name={groupName}
          value="all"
          checked={value === "all"}
          onChange={() => onChange("all")}
        />
        All
      </label>

      <label>
        <input
          type="radio"
          name={groupName}
          value="active"
          checked={value === "active"}
          onChange={() => onChange("active")}
        />
        Active
      </label>

      <label>
        <input
          type="radio"
          name={groupName}
          value="completed"
          checked={value === "completed"}
          onChange={() => onChange("completed")}
        />
        Completed
      </label>
    </fieldset>
  );
}

export default function App() {
  const [initialStore] = useState(loadTaskStore);
  const [tasks, setTasks] = useState(initialStore.tasks);
  const [storageWarning, setStorageWarning] = useState(initialStore.warning);
  const [hasLocalChanges, setHasLocalChanges] = useState(false);
  const [searchText, setSearchText] = useState("");
  const [filter, setFilter] = useState("all");
  const searchId = useId();

  useEffect(() => {
    if (!hasLocalChanges) {
      return;
    }

    try {
      saveTasks(tasks);
      setStorageWarning("");
    } catch {
      setStorageWarning(
        "The task list still works, but this browser could not save changes."
      );
    }
  }, [hasLocalChanges, tasks]);

  function updateTasks(change) {
    setTasks((currentTasks) => change(currentTasks));
    setHasLocalChanges(true);
  }

  function addTask(title) {
    const newTask = {
      id: createTaskId(),
      title,
      completed: false,
    };

    updateTasks((currentTasks) => [...currentTasks, newTask]);
  }

  function toggleTask(taskId) {
    updateTasks((currentTasks) =>
      currentTasks.map((task) =>
        task.id === taskId
          ? { ...task, completed: !task.completed }
          : task
      )
    );
  }

  function deleteTask(taskId) {
    updateTasks((currentTasks) =>
      currentTasks.filter((task) => task.id !== taskId)
    );
  }

  function clearCompleted() {
    updateTasks((currentTasks) =>
      currentTasks.filter((task) => !task.completed)
    );
  }

  const completedCount = tasks.filter((task) => task.completed).length;
  const activeCount = tasks.length - completedCount;
  const normalizedSearch = searchText.trim().toLocaleLowerCase();

  const visibleTasks = tasks.filter((task) => {
    const matchesSearch = task.title
      .toLocaleLowerCase()
      .includes(normalizedSearch);

    const matchesFilter =
      filter === "all" ||
      (filter === "active" && !task.completed) ||
      (filter === "completed" && task.completed);

    return matchesSearch && matchesFilter;
  });

  const hasSearchOrFilter = normalizedSearch !== "" || filter !== "all";

  return (
    <main className="app-shell">
      <header className="page-header">
        <p className="eyebrow">A small React capstone</p>
        <h1>Task list</h1>
        <p>
          Capture a task, make progress, and keep the list organized.
        </p>
      </header>

      <section className="panel" aria-labelledby="add-task-heading">
        <h2 id="add-task-heading">Add a task</h2>
        <TaskForm onAddTask={addTask} />
      </section>

      <section className="panel" aria-labelledby="tasks-heading">
        <div className="section-heading">
          <div>
            <h2 id="tasks-heading">Your tasks</h2>
            <p className="task-count" aria-live="polite" aria-atomic="true">
              {tasks.length} total, {activeCount} active, {completedCount} completed
            </p>
          </div>

          {completedCount > 0 && (
            <button
              className="button-secondary"
              type="button"
              onClick={clearCompleted}
            >
              Clear completed
            </button>
          )}
        </div>

        <div className="task-controls">
          <div className="search-control">
            <label htmlFor={searchId}>Search tasks</label>
            <input
              id={searchId}
              type="search"
              value={searchText}
              onChange={(event) => setSearchText(event.target.value)}
              placeholder="For example, keyboard"
            />
          </div>

          <TaskFilters value={filter} onChange={setFilter} />
        </div>

        {tasks.length === 0 ? (
          <p className="empty-state">
            Your list is empty. Add a task above to get started.
          </p>
        ) : visibleTasks.length === 0 ? (
          <p className="empty-state">
            No tasks match this search and filter. Change them to see more tasks.
          </p>
        ) : (
          <ul className="task-list" aria-label="Tasks">
            {visibleTasks.map((task) => (
              <TaskItem
                key={task.id}
                task={task}
                onToggle={toggleTask}
                onDelete={deleteTask}
              />
            ))}
          </ul>
        )}

        {tasks.length > 0 && hasSearchOrFilter && visibleTasks.length > 0 && (
          <p className="result-count">
            Showing {visibleTasks.length} of {tasks.length} tasks.
          </p>
        )}
      </section>

      {storageWarning && (
        <p className="storage-warning" role="status">
          {storageWarning}
        </p>
      )}

      <footer className="page-footer">
        <p>
          Tasks are saved in this browser only. Do not enter passwords or
          sensitive information.
        </p>
      </footer>
    </main>
  );
}
```

The only authoritative task state is the task array. Search results and counts are calculated during rendering. Task changes create new arrays and objects; they do not mutate existing state.

The storage Effect runs only after a task change. If a read fails at startup, the warning remains and the starter list is not immediately written over the saved value. When the visitor changes a task, the app attempts to save the current list.

## 7. Mount the application

Replace `src/main.jsx` with:

```jsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
);
```

Keep the Vite-provided `index.html` with a root element and a module script pointing to `/src/main.jsx`.

## 8. Review the interaction flows

Try these checks in the browser:

1. Add a title with spaces around it and confirm the rendered task is trimmed.
2. Submit a blank or whitespace-only title and confirm the form explains the problem.
3. Complete and uncomplete a task with the checkbox.
4. Delete one task and confirm the others stay unchanged.
5. Search for a word using different letter casing.
6. Select All, Active, and Completed and confirm each list.
7. Clear completed and confirm active tasks remain.
8. Refresh the page and confirm a changed list returns.
9. Search for a value with no result, then clear the search.
10. Use keyboard navigation to reach every input and button and confirm focus remains visible.
11. Resize to a narrow viewport and verify the controls remain usable.
12. In browser developer tools, remove or corrupt the saved key and reload to review the warning and fallback behavior.
13. Disable browser storage if possible, then add a task and confirm the app remains usable with a warning.

The `Clear completed` button is rendered only when completed tasks exist. The initial empty list and a search with no matches have different messages.

## 9. Build for release

Run the production build:

```sh
npm run build
```

Resolve build errors, then preview or deploy the generated output using the hosting process for your project. Confirm that the deployed base path and static asset configuration are correct. Do not add secret credentials to frontend environment variables.

## 10. Project extensions

After the base version works, possible follow-up work includes:

- edit an existing task title;
- sort by creation or completion;
- add categories and category filters;
- add an undo action after deletion;
- write focused component and browser tests;
- replace local storage with an authenticated API;
- add conflict handling for updates from multiple tabs or devices; and
- add production error reporting and release monitoring.

Keep the data model and access rules clear before adding these features. The local version is a complete single-browser learning project, not a multi-user task service.
